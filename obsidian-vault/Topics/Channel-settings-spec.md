# Настройки канала — продуктовая спецификация (Telegram-parity + кастом)

> **Назначение:** один файл контекста для ИИ/разработки. Текущий UI настроек канала в приложении скудный; цель — расширить по образцу Telegram (скрины референса), с перечисленными ниже правилами.

**Связано:** [[Channels]], [[../Home|Home]].

---

## Не переносим (игнор)

Из референса Telegram **не** делаем в этой итерации:

- Автоперевод сообщений  
- «Сообщения каналу» (монетизация / paid messages)  
- Недавние действия (аудит лога)  
- Партнёрские программы  

---

## Экран «Настройки канала» — какие блоки переносим

Сверху уровня меню (как на первом скрине референса), **включаем разделы**:

| Раздел | Суть |
|--------|------|
| Тип канала | Публичный / частный + публичная ссылка + приглашения |
| Обсуждение | Комментарии: лимиты, запреты по типу контента, таймер между сообщениями |
| Реакции | Запретить реакции **или** разрешить (пока бинарно) |
| Администраторы | Список + счётчик (как в TG) |
| Подписчики | Список + счётчик |
| Чёрный список | Заблокированные; разблокировка |

**Дополнительно:** блоки «Администраторы» и «Подписчики» дублируют информацию, которая частично видна **до** входа в настройки — **всё равно показываем** внутри настроек канала (удобство и паритет с TG).

---

## 1. Тип канала (второй скрин — референс)

**Функционал (must):**

1. **Выбор типа**
   - **Публичный** — канал находится через поиск; любой может подписаться (в рамках правил продукта).
   - **Частный** — без публичного slug / только по инвайту (логика как в TG: недоступен публичный поиск по ссылке в том виде, как у публичного).

2. **Публичная ссылка** (для публичного канала)
   - Вид: `t.me/<slug>` у нас — **аналог** внутреннего бренда (например `app.me/<slug>` или тот же хост, что в API) — в спеке зафиксировать как **единый префикс + slug**.
   - **Правила slug:** латиница `a-z`, цифры `0-9`, подчёркивание `_`; **минимум 5 символов**.
   - Поле редактируемое; кнопка очистки (как «×» на референсе).

3. **Приглашения**
   - Пункт **«Управление приглашениями»**: возможность создавать **дополнительные** ссылки, задавать **срок действия** и/или **лимит числа пользователей** по ссылке (как у Telegram).

**Исключено:** всё, что не относится к типу/ссылке/инвайтам.

---

## 2. Обсуждение (комментарии к постам)

Отдельный блок настроек. **Пункты (все задаются независимо, уточнить дефолты при имплементации):**

| Пункт | Поведение |
|-------|-----------|
| Отключить комментарии **к новым** постам | Новые посты публикуются без возможности комментировать (старые посты не трогаем, если не включён следующий пункт). |
| Отключить комментарии **для всех** постов | И для уже существующих, и для новых — комментарии везде выключены. |
| Запретить **голосовые** в комментариях | Пользователь не может отправить voice в тред обсуждения. |
| Запретить **медиа** в комментариях | Нельзя прикладывать фото и видео (явно перечислить типы в API/валидации). |
| **Таймер между сообщениями** | Минимальный интервал **от 1 до 15 секунд** между **новым** сообщением одного пользователя в обсуждении (анти-флуд). Значение — выбор из диапазона **1…15** сек. |

**Заметки для реализации:**

- При конфликте «только новые» vs «все посты» — правило **«все посты» сильнее** (глобальный запрет комментариев перекрывает только «новые»).
- Таймер применяется к **отправке в discussion** (текст/медиа/voice — уточнить единообразно: обычно ко всем исходящим сообщениям пользователя в треде).

---

## 3. Реакции

- Пока **просто:** либо **разрешить реакции**, либо **запретить реакции** (один переключатель / enum).
- Расширение «как в TG — набор эмодзи» — **не** в этом ТЗ (можно запланировать отдельно).

---

## 4. Чёрный список

- Пользователь после **блокировки** подписчика попадает в **чёрный список**.
- Оттуда доступны: просмотр, **разблокировка** (вернуть в подписчики по правилам продукта).

---

## 5. Администраторы и подписчики

- Отображение **списка + счётчики** (как на референсе: «Администраторы: N», «Подписчики: N»).
- Переход в детальные экраны списков — в рамках существующей навигации приложения; **дублирование** с тем, что видно до настроек — **ок**.
