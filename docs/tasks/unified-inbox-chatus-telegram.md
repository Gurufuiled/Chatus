# Задача: единый список чатов (Chatus + Telegram)

**Трек:** клиент `mobile/` (навигация, список чатов, сторы).  
**Не входит:** сервер relay/P2P (`docs/p2p/` — см. границы в [../p2p/06-unified-inbox-telegram-scope.md](../p2p/06-unified-inbox-telegram-scope.md)).

---

## Цель

После входа в Chatus пользователь может **привязать Telegram в настройках**. На вкладке «Чаты» отображается **один общий список**: диалоги Chatus и диалоги Telegram **без переключателя** «сейчас показываю только Loginus / только Telegram».

До привязки Telegram поведение остаётся как для нативных чатов Chatus (список только Chatus).

---

## Текущее состояние (ориентиры в коде)

| Место | Роль |
|-------|------|
| `mobile/src/stores/inboxModeStore.ts` | Режим `loginus` \| `telegram`, персист в SecureStore. |
| `mobile/src/screens/ChatListScreen.tsx` | При `activeInbox === 'telegram'` рендерится `<TelegramDialogsScreen />`, иначе список Chatus. |
| `mobile/src/navigation/ChatsStack.tsx` | Заголовок и действия зависят от `activeInbox`. |
| `mobile/src/navigation/MainTabs.tsx` | Long-press / выбор режима инбокса, `hydrate` для `inboxModeStore`. |
| `mobile/src/screens/SettingsScreen.tsx`, `TelegramAuthScreen.tsx` | Переключение на telegram-режим после действий. |
| `mobile/src/screens/TelegramDialogsScreen.tsx` | Список tg-диалогов. |

Эти точки — кандидаты на рефакторинг под **единый список** (не обязательно удалять стор сразу; можно свести `activeInbox` к устаревшему или заменить на флаг «TG привязан»).

---

## Требования к реализации

1. **Источник строки** — у каждого элемента списка явно: `source: 'chatus' | 'telegram'` (или эквивалент), чтобы не путать ID чатов и маршруты.
2. **Сортировка** — единое правило (например по `last_message_at` / аналог из TDLib); зафиксировать в коде и кратко здесь после выбора.
3. **Навигация** — тап открывает либо экран нативного чата, либо Telegram-чата (уже существующие экраны; возможно общая обёртка-роутер по `source`).
4. **При отвязке / выходе из Telegram** — tg-строки исчезают из объединённого списка; состояние Chatus не ломается.
5. **Без регресса** для пользователя **без** привязки TG: только Chatus, без пустых блоков и лишних шагов.

---

## Критерии приёмки

- [ ] Один экран списка показывает и Chatus, и Telegram-диалоги после успешной привязки аккаунта.
- [ ] Нет UI-переключателя «показать только Telegram / только Chatus» на главном списке (допустимы фильтры поиска позже — отдельно).
- [ ] Заголовок вкладки «Чаты» и primary-действия не завязаны на старый бинарный режим так, что ломают объединённый вид (уточнить финальный UX в PR).
- [ ] Нет коллизий ID: открывается корректный чат для выбранной строки.
- [ ] Ручная проверка: привязка TG → смешанный список → открытие чатов обоих типов → выход из TG / отвязка → только Chatus.
