# P2P-first и mailbox на сервере (документация планирования)

Папка описывает **пошаговое внедрение** целевой модели для нативного мессенджера Chatus:

- **P2P-first:** в личке 1:1 в первую очередь доставка **напрямую между клиентами**, когда это возможно.
- **Сервер как временное хранилище и фолбэк:** если получатель недоступен для peer, не удалось установить соединение или по политике нужен relay — сообщение обрабатывается через **NestJS / WebSocket / mailbox**, с правилами **TTL и очистки** (`RELAY_*`).

Интеграция с текущим стеком (HTTP, WebSocket, SQLite, загрузки медиа) и **куда встраивать** изменения — в файлах ниже.

**Единый список чатов Chatus + Telegram** не отменяет этот план для нативного контура; Telegram остаётся на TDLib. Подробнее: [06-unified-inbox-telegram-scope.md](./06-unified-inbox-telegram-scope.md).

## Быстрый консенсус для команды

- **Цель продукта:** не «всегда через сервер», а **сначала peer**, сервер — **буфер и надёжный запасной путь**, а не единственная труба для онлайн-лички.
- **Группы и каналы:** центральный сервер почти неизбежен для привычного UX; P2P там — опциональное усиление, не замена учёта.
- Поле **`transport`** (`websocket` \| `p2p`) отражает **как прошло сообщение** (через серверный relay или через peer-путь).
- **Текущая реализация в репозитории** до завершения фаз по-прежнему **server-first**; документы описывают **целевое** состояние и переход.

Дальнейшие правки — по мере спайков и созвонов; код меняется по фазам из [03-rollout-phases.md](./03-rollout-phases.md).
