## 2024-07-05 - [O(1) read receipts iteration]
**Learning:** In the mobile app, chat messages arrays (e.g., from `messageStore`) are strictly sorted newest-first. When iterating over messages to check or update chronological statuses (like read receipts), the iteration process can be turned from O(N) into O(1) amortized by breaking early once an already-processed message is found, since older messages can be safely assumed to be processed as well.
**Action:** When writing loops that iterate over message arrays to resolve chronological state, always consider breaking the loop early to avoid unnecessary full-array traversals.
