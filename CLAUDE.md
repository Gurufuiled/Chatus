# Chatus — правила для работы в репозитории

## Ветки

- **`main`** — Android-версия и релизы. Все правки Android делаются здесь.
- **`dev-vlad`** — iOS-ветка. Не трогать, не мержить в неё и не коммитить туда из задач по Android.

## Тесты — обязательное правило

Любое изменение поведения приложения идёт **вместе с тестами**. Покрытие в проекте пока маленькое, поэтому правило такое: **каждая затронутая часть приложения получает тест**, даже если раньше его не было.

1. **Новая логика → тест.** Любая новая или изменённая функция, расчёт, форматирование, парсер, правило отправки, выбор транспорта и т.п. получает `*.test.ts` рядом с файлом.
2. **Исправление бага → регрессионный тест.** Сначала тест, который воспроизводит баг (падает), потом фикс.
3. **UI и жесты.** Саму отрисовку и «ощущение» жеста на устройстве тестом не поймать, поэтому логику (математику жеста, пороги, выбор состояния, раскладку, форматирование) выносим в чистый модуль без импортов `react-native` / `reanimated` и тестируем его. Компонент остаётся тонкой обвязкой. Пример: `formatMessageTimeCore.ts` + `formatMessageTime.test.ts`.
4. **Поведение компонента** (что рендерится, что вызывается по нажатию) — `@testing-library/react-native`, файл `*.test.tsx` рядом с компонентом. Запускать точечно: `npx jest src/components/Foo.test.tsx` (общий `npm run test:jest` захватывает и старые `*.test.ts` в формате `tsx`, и они под jest падают). Нативные модули (Reanimated, gesture-handler) в jest подменяем моками, пример: `src/hooks/useHeroDismiss.test.tsx`.
5. Если что-то реально нельзя покрыть тестом (нативный модуль, камера, анимация), **явно напиши об этом** в итоговом сообщении и покрой всё, что можно, вокруг этого.
6. Не удалять и не ослаблять существующие тесты, чтобы «позеленело». Если тест устарел из-за осознанного изменения поведения, обнови его и объясни почему.

### Как писать

- Файлы `*.test.ts` под `mobile/src/`, самозапускающиеся: `import assert from 'node:assert/strict'` и в конце `console.log('<имя>.test.ts: ok')`.
- Автоматически подхватываются раннером `mobile/scripts/run-unit-tests.mjs` (только `*.test.ts`; `*.test.tsx` раннер не запускает).
- Чистую логику держим в отдельных модулях (`*Core.ts`, `*Math.ts`, `*Utils.ts`), которые импортируются в `tsx` без Expo/RN.

### Перед тем как сказать «готово»

Из каталога `mobile/`:

```bash
npx tsc --noEmit   # типы
npm test           # все *.test.ts
```

Если команда падает — скажи об этом и покажи вывод, не пиши «готово».

## Сборка Android (кратко)

- Прод-сборка: `MOBILE_ENV=production`, переменные из `mobile/.env.production` (API `https://messenger.startapus.com/api`).
- `mobile/android/` в `.gitignore`: Expo может пересоздать её при `expo run:android`.
- Установка на телефон по USB у Xiaomi требует включённой «Установки через USB» в настройках для разработчиков.
