# Boss Preference Summary

## Что руководитель хочет по-простому

Руководитель предлагает упростить задачу и не строить сейчас сложную встроенную monetization-систему.

### 1. Не ждать `Счетус`

Не нужно откладывать запуск каналов из-за внутреннего биллинга.

### 2. Ввести права аккаунта

Если у пользователя есть нужный платный тариф аккаунта, ему можно:

- создавать группы;
- создавать паблики/каналы.

Если такого тарифа нет, ему остаются:

- общение;
- обычные чаты.

### 3. Деньги автора вынести наружу

Автор канала должен получать деньги не через внутреннюю систему приложения, а через внешний сервис в своем аккаунте.

### 4. Приложение должно управлять доступом

Внутри приложения нужно оставить:

- список тех, кому можно быть в канале;
- API для сверки доступа;
- возможность исключить участника, если доступ отозван.

## Что это значит для продукта

Платформа сейчас становится не биллинговой системой, а системой:

- прав;
- ролей;
- доступа;
- модерации участников.

## Что это значит для backend

Backend не обязан:

- принимать деньги за подписку на канал;
- считать доход автора;
- считать комиссию сервиса;
- хранить payout balance;
- делать выплаты.

Backend обязан:

- знать, кому разрешено создавать канал;
- знать, кому разрешено находиться в канале;
- быстро отзывать доступ.

## Что это значит для mobile

Mobile должен:

- показывать создание канала только тем, у кого есть право;
- показывать экран доступа/закрытого канала;
- при необходимости показывать кнопку перехода к внешней оплате;
- позволять владельцу канала видеть список участников и исключать их.

## Текущий управленческий вывод

Сейчас важнее всего не встроенная оплата, а:

- запуск каналов;
- права аккаунтов;
- управление участниками;
- внешняя монетизация автора через выбранный сервис.
